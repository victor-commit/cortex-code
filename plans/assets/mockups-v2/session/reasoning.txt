   Cortex

   The 500 comes from stale session rows, not the login handler itself. The deploy added
   a non-null token_version column, but sessions created before the migration still hold null,
   so the token-refresh query fails for those users. Two fixes worth applying together:

   1  Backfill   set token_version = 1 for every row where it is currently null
   2  Guard      treat a null token_version as version 0 instead of failing the refresh

   ● In short  backfill the null rows, then make the refresh path tolerate them.
