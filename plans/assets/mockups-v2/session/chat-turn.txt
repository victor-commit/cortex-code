

















 › why are stale sessions rejected after a password change?  · 5m ago

   Cortex

   Every session token embeds the token_version that was current when it was issued.
   Changing the password bumps the stored version, so the next request presents a stale token
   that no longer matches.

   The comparison happens in enforce(), which runs before any handler. A version mismatch is
   rejected with 401 before rate limiting is even consulted; genuine rate-limit rejections use
   429 instead, so clients can tell the two cases apart.

   Treat that rejection as a signal to re-authenticate rather than retry: enforce() keeps
   rejecting the old token until a fresh sign-in issues a new one.

   ● In short  a password change bumps token_version; every older token then gets 401.
